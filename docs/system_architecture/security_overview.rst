##########################################################
NVIDIA FLARE セキュリティ概要
##########################################################

セキュリティアーキテクチャの詳細に入る前に、FLARE のシステムアーキテクチャを理解しておくと役立ちます: :ref:`flare_system_architecture`

連合コンピューティングシステムにおけるセキュリティ
====================================================================

連合学習における重要なセキュリティ上の懸念事項
--------------------------------------------------------------------

**データプライバシー**

- モデル反転攻撃、メンバーシップ推論攻撃、プロパティ推論攻撃からトレーニングデータを保護する
- パラメーター共有時の勾配リークを防止する

**システムセキュリティ**

- 参加者を認証し、中間者攻撃、Sybil 攻撃、DoS 攻撃を防止する
- モデルと勾配の安全な送信を保証する

**モデルセキュリティ**

- モデルポイズニング、バックドア攻撃、窃取、敵対的操作から防御する

**参加者のプライバシー**

- 参加者の身元、参加状況、組織の知的財産を保護する

**計算の完全性**

- 正しい計算を検証し、悪意のある更新や不正な更新を検出する
- FL プロトコルの誠実な実行を保証する

**アクセス制御**

- ロールベースの権限、リソース使用量の制限、データ・モデルへのアクセス制限を適用する

**規制コンプライアンス**

- データ保護規制(GDPR、HIPAA など)に準拠する
- 国境を越えるデータガバナンスと監査証跡を維持する

**インフラストラクチャセキュリティ**

- エッジデバイス、サーバー、通信チャネル、モデルストレージを保護する


NVIDIA FLARE セキュリティアーキテクチャ
================================================================

NVIDIA FLARE は、連合学習システムを保護するための堅牢なセキュリティ対策を備えて設計されています。そのセキュリティフレームワークは、組み込みのアプリケーション機能と各サイトの既存の IT インフラストラクチャを組み合わせたものです。

セキュリティの柱
--------------------------------

FLARE は、複数のセキュリティの柱を通じて重要なセキュリティ上の懸念事項に対処します:

.. list-table::
   :header-rows: 1
   :widths: 25 50 25

   * - セキュリティ領域
     - 説明
     - 詳細情報
   * - **アイデンティティとアクセス制御**
     - PKI ベースの認証、ロールベースの認可、サイトごとのポリシー、サイト固有の認証統合
     - :ref:`アイデンティティセキュリティ <identity_security_page>`、:ref:`サイトポリシー管理 <site_policy_management>`、:ref:`用語とロール <nvflare_roles>`
   * - **ネットワークと通信**
     - TLS/mTLS 暗号化、明示的なメッセージ認証、BYO 接続、プロキシサポート、安全なシリアライゼーション(FOBS)
     - :ref:`通信セキュリティ <communication_security>`
   * - **データプライバシーとフィルター**
     - プライバシー保護フィルター(差分プライバシー、準同型暗号)、ジョブごと・サイトごとのフィルターチェーン
     - :ref:`データプライバシー保護 <data_privacy_protection>`
   * - **監査とコンプライアンス**
     - すべてのユーザーコマンドとジョブイベントの包括的な監査ログ、サイト間で相関付けられたイベント追跡
     - :ref:`監査 <auditing>`
   * - **コンポーネントの安全性**
     - 実行前の安全でないジョブコンポーネントのイベントベース検出により、信頼できないコードからのデータ漏洩を防止
     - :ref:`安全でないコンポーネントの検出 <unsafe_component_detection>`
   * - **コンフィデンシャルコンピューティング**
     - ハードウェアベースの TEE(AMD SEV-SNP、NVIDIA GPU)による安全な集約、モデル知的財産の保護、データ漏洩の防止
     - :ref:`コンフィデンシャルコンピューティング <confidential_computing>`

主要な原則
--------------------

- **生データを移動しない** -- 生データが参加機関の外に出ることはなく、送信されるのはモデル更新のみです
- **連合認可** -- 各組織が独自の認可ポリシーを定義・適用します(中央集権的ではありません)
- **サイト固有の認証** -- 各サイトは独自の認証システム(KeyCloak、OAuth など)を統合できます
- **多層防御** -- アイデンティティ検証からコンフィデンシャルコンピューティングまで、複数のセキュリティレイヤーを備えています


連合セキュリティ: ローカルサイトによる制御
================================================================

NVIDIA FLARE のセキュリティアーキテクチャの基本原則は、**各参加サイトが自身のセキュリティを完全に制御し続ける**\ ことです。単一の管理主体がセキュリティポリシーを決定する中央集権型システムとは異なり、FLARE は連合セキュリティモデルを採用しており、病院、銀行、政府機関などの組織は、FLARE を自組織の既存のセキュリティインフラストラクチャに統合します -- その逆ではありません。

**連合セキュリティが重要な理由**

実際の連合学習のデプロイメントでは、各参加機関はそれぞれ独自の以下を持っています:

- IT セキュリティポリシーとコンプライアンス要件(HIPAA、SOX、GDPR など)
- 認証システム(Active Directory、LDAP、KeyCloak、OAuth など)
- ネットワークセキュリティインフラストラクチャ(ファイアウォール、プロキシ、VPN)
- データガバナンスとアクセス制御ポリシー

FLARE は、これらすべてを尊重し、統合できるように設計されています。中央の管理主体がローカルサイトのセキュリティ上の決定を覆すことはできません。

**仕組み**

- **ローカル認証** -- 各サイトは独自の認証メカニズムを組み込むことができます。KeyCloak を使用する病院と LDAP を使用する銀行は、認証システムを変更することなく同じ FL プロジェクトに参加できます。FLARE のイベントベースのプラグインフレームワークにより、各サイトでカスタム認証器を使用できます。:ref:`アイデンティティセキュリティ <identity_security_page>` を参照してください。

- **ローカル認可** -- 各サイトは、そのサイト上でユーザーが実行できることとできないことを定める独自の認可ポリシーを定義します。サイトは、実行を許可するジョブ、使用できるリソース、アクセス権を持つユーザーを制限できます。中央の FL サーバーがサイトの認可の決定を覆すことはできません。:ref:`サイトポリシー管理 <site_policy_management>` を参照してください。

- **ローカルプライバシーポリシー** -- 各サイトは独自のプライバシー保護ルールを定義します。例えば、病院は、ジョブ設定の内容にかかわらず、サイトから出るすべてのモデル更新に差分プライバシーフィルターを適用することを必須にできます。サイトレベルのプライバシーポリシーは、常にジョブレベルの設定より優先されます。:ref:`データプライバシー保護 <data_privacy_protection>` を参照してください。

- **ローカルリソース制御** -- 各サイトは自身の計算リソース(GPU、メモリ、ストレージ)を制御し、FL ジョブが消費できる量に制限を設けることができます。

- **ローカルネットワークセキュリティ** -- サイトは自身のファイアウォールとネットワークポリシーの内側で運用されます。FLARE は TLS、mTLS、プロキシ、BYO 接続をサポートしており、あらゆるネットワーク環境内で動作します。:ref:`通信セキュリティ <communication_security>` を参照してください。

この連合アプローチにより、単一の侵害ポイントがシステム全体に影響を及ぼすことがなくなり、各機関は独立して自身の規制・コンプライアンス要件を満たすことができます。


データストレージ、インフラストラクチャ、コンプライアンスに関するよくある質問については、:ref:`セキュリティ FAQ <security_faq>` を参照してください。
