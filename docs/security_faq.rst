##################################
セキュリティ FAQ
##################################

データはどこに保存されますか?
============================================================

データは各機関のローカルストレージ(オンプレミスまたはプライベートクラウドアカウント)に保存されます。FLARE がデータを移動することはありません。

中央の連合サイトにはどのような結果が共有されますか?
========================================================================

「中央の連合サイト」は、NVFlare では「FL サーバー」と呼ばれます。最終結果の保存場所はアグリゲーター(集約器)の場所に依存し、アルゴリズムによって異なります。

- **FedAvg 型ワークフローの場合** -- アグリゲーターは FL サーバーにあり、最終結果は FL サーバーからアクセス可能なローカルディスクまたはボリュームであるジョブストアに保存されます
- **Swarm learning アルゴリズムの場合** -- アグリゲーターは各ラウンドで全参加サイトの中からランダムに選ばれ、最終結果はそのサイトのローカルに保存され、FL サーバーには共有されません

いずれの場合も、アグリゲーターには最新のセキュリティ・プライバシーのベストプラクティスを適用してロックダウンしたマシンを使用できます。コンフィデンシャルコンピューティングは、さらなるセキュリティレイヤーを追加する最新技術です。

IRB 番号はどうなりますか?
================================================

コンソーシアムの参加者は、それぞれの機関の要件に従って IRB プロセスを処理します。

ローカルには何をインストールする必要がありますか?
========================================================================

FLARE のローカルインストールには以下の手順があります:

1. **プロビジョニング** -- 各参加者向けのソフトウェアパッケージと証明書(スタートアップキットと呼ばれます)を生成するプロセス
2. **配布** -- スタートアップキットを各参加者に送付
3. **起動** -- 参加者は pip install nvflare を実行し、スタートアップキットを起動

FLARE はプロビジョニングの方法を2つ提供しています:

- **nvflare provision CLI コマンド** -- パッケージがローカルに生成され、プロジェクト管理者が手動(sftp、メールなど)でパッケージを配布します
- **FLARE Dashboard** -- Web インターフェースにより、プロジェクト管理者は他の参加者をプロジェクトに招待し、参加者自身にサイト固有の情報を入力してもらうことができます

詳細は :ref:`installation` と :ref:`deployment_overview` を参照してください。

各機関側のインフラストラクチャはどのようなものですか?
========================================================================

知的財産保護を伴うコンフィデンシャルコンピューティングを活用したい場合を除き、FLARE は特定の種類のインフラストラクチャを必須としません。CPU でも GPU でも実行できます。最小要件は、Linux ディストリビューション(Ubuntu など)が動作する 8GB の CPU マシンです。ディープラーニングモデルの場合、トレーニングを高速化するために GPU が必要になります。

こちら側で Docker を実行する必要がありますか?
========================================================================

いいえ、必須ではありません。希望する場合は Docker を使用できます。

Red Hat 上で動作しますか?
==================================================

はい。

FLARE は誰が保守していますか?
============================================================

NVIDIA FLARE はオープンソースプロジェクトであり、NVIDIA と NVFLARE コミュニティによって貢献・保守されています。

このソフトウェアは、寛容なオープンソースライセンスである Apache 2.0 License の下で配布されています。このライセンスの下では、ソフトウェアは保証や責任なしに「現状のまま」提供されます。

正式なサポートや補償が必要な場合は、Apache 2.0 ライセンスのソフトウェアに対する商用サポートを提供するサードパーティのサービスプロバイダーを通じて取得できます。

機関の外に出た後のデータの所有者は誰ですか?
========================================================================

生データが機関の外に出ることは一切ありません。送信されるのはモデル重みのみです。

トレーニングされたモデルの所有者は、協業契約に応じて参加者間で異なります。NVIDIA FLARE はこうしたビジネス上の決定には関与しません。

データ利用契約はありますか?
========================================================

データが機関の外に出ることはないため、通常、特定のデータ利用契約はありません。ただし、共同でモデルをトレーニングするためにどのデータを使用するかは、通常、協力者間で決定する必要があります。

コードはプロキシに対応していますか?
============================================================

はい、NVIDIA FLARE は、リバースプロキシや Kubernetes の ingress サービスなど、プロキシを含むネットワークトポロジーを介して動作できます。

FLARE は2種類の TLS プロトコルをサポートしています: 相互 TLS(mutual TLS)と標準 TLS です。

- **相互 TLS の場合** -- 証明書の終端点はプロキシではなくサーバーにあります。プロキシは TCP パススルーを有効にするように設定する必要があります
- **標準 TLS の場合** -- ユーザーは、TLS ハンドシェイクには事前認可された証明書を、認証には FLARE の証明書をそのまま使用できます

詳細は :ref:`通信セキュリティ <communication_security>` と :ref:`サーバーポートの集約 <server_port_consolidation>` を参照してください。
