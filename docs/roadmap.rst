####################################################
NVIDIA FLAREロードマップ
####################################################

このページでは、今後のNVIDIA FLAREバージョンで計画されている機能と目標リリースマイルストーンを概説します。
日程および機能は変更される可能性があります。

.. note::
   注記: このロードマップは現時点の計画を反映したものであり、情報提供を目的として提供されています。
   機能の範囲やリリース時期は、開発の進行に伴い変わる可能性があります。

****************************************************************
FLARE 2.8.0 — 目標: 2026年第2四半期
****************************************************************

**ネイティブKubernetesサポート**

- 親コントロールPodとジョブ実行Podを分離し、独立したライフサイクル管理とより良いリソース分離を実現
- 主要なクラウドKubernetes環境(GKE、EKS、AKS、オンプレミス)へのデプロイメントを簡素化

**Dockerデプロイメントの改善**

- KubernetesのPod分離モデルにならい、親コンテナとジョブ実行コンテナを分離
- 一般的なデプロイメントシナリオ向けにすぐに使えるDockerfileを提供し、セットアップの手間を削減

**マルチスタディサポート**

- 単一のFLAREデプロイメント内で複数のスタディを同時に実行可能に
- DockerおよびKubernetesのPodレベルのデータ分離により、スタディ間のデータ分離を強制

**分散プロビジョニング**

- サイト管理者がローカルで自身の鍵ペアを生成し、プロジェクト管理者から署名済み証明書を受け取れる分散プロビジョニングワークフローを実現
- 秘密鍵の集中生成と配布の必要性を排除

**CLIコマンドの拡充**

- FLARE Admin Consoleの全コマンドをカバーするように ``nvflare`` CLIを拡張
- 対話型コンソールを必要とせず、コマンドラインから完全な管理制御が可能に

**サーバー側メモリ最適化**

- 連合学習ジョブ実行中のサーバー側メモリ使用量を削減
- 大規模モデルおよび大規模データセットのワークロード向けにメモリ管理を改善

****************************************************************
FLARE 2.9.0 — 目標: 2026年第3四半期
****************************************************************

**新しいCollab API**

- 研究の生産性向上を目的とした新しいCollaboration (Collab) APIを導入
- ボイラープレートを削減し、より柔軟で組み合わせ可能なFLワークフロー定義を実現

**FLARE Agent対応**

- AIエージェントワークフローのバックエンドとしてFLAREを利用可能にするプラットフォーム機能

**Kubernetesユーザーエクスペリエンスの向上**

- 2.8.0の基盤の上に構築される、簡素化されたKubernetesデプロイメントと運用体験
- マルチサイトKubernetesデプロイメントを管理するデータサイエンティストとオペレーター向けのユーザビリティ改善

**Slurmサポート**

- HPCクラスター環境向けのSlurmワークロードマネージャーとのより良い統合
- Slurm管理下のコンピューティング環境内でFLジョブをネイティブに実行可能に

******************************************************************
FLARE 2.10.0 — 目標: 2026年第4四半期
******************************************************************

**Kubernetesの高度な機能強化**

- これまでのリリースの上に構築されるKubernetesの高度な機能セット
- 大規模なマルチサイトKubernetesデプロイメント向けの、より深いプラットフォーム統合と運用制御

**コンフィデンシャル連合AIのサポート**

NVIDIA GPUを搭載したAMD SEV-SNP CPU CVMおよびAzure Confidential Computingの既存サポートを基盤として:

- CPUベースのコンフィデンシャルコンピューティングワークロード向けのIntel TDX CPUサポート
- コンテナレベルのコンフィデンシャル実行のためのCoCo (Confidential Containers)サポート
- Azureを超えて他の主要クラウドプラットフォームへ拡大するCloud Service Provider (CSP)統合
