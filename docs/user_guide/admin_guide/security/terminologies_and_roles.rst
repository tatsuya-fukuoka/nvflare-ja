**********************
用語とロール
**********************

用語
==========
背景知識の確立のため、いくつかの用語を示します。

Project
------------
参加者が特定された FL スタディです。

Org
--------
スタディに参加する組織です。

Site
--------
スタディの一部として NVFLARE アプリケーションを実行するコンピューティングシステムです。
サイトにはサーバーとクライアントの2種類があります。
各サイトはいずれかの組織に属します。

FL Server
------------
サーバーサイト上で動作するアプリケーションで、連合ワークフローに基づいてクライアントの調整を担います。各プロジェクトには1つ以上の FL サーバーを配置できます。

FL Client
----------
クライアントサイト上で動作するアプリケーションで、サーバーのタスク割り当てに応答し、ローカルデータに基づいて学習アクションを実行します。

User
--------
FL プロジェクトに参加する人間です。

.. _nvflare_roles:

Role
--------
ロールは、システム運用に関する特定の権限を持つユーザーの種類を定義します。各ユーザーには、プロジェクトにおいてロールが割り当てられます。定義されているロールは、Project Admin、Org Admin、Lead Researcher、Member Researcher の4つです。

.. _project_admin_role:

Project Admin ロール
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
Project Admin は、参加者のプロビジョニングと、プロジェクトに関わる全サイトの担当者の調整を担います。
ダッシュボード UI を使用する場合、Project Admin はサイトの管理者として、最初にプロジェクトをセットアップするための値を入力し、その後、必要に応じて編集を行いながらユーザーとクライアントサイトを承認する責任を負います。

Project Admin は FL サーバーの管理も担います。

各プロジェクトの Project Admin は1名のみです。

Org Admin ロール
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
このロールは、自身の組織のサイトの管理を担います。

Lead Researcher ロール
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
このロールは、プロジェクトの成功を確実にするために他の研究者と協働する科学者に対して、組織内でより高い権限を与えるように設定できます。

Member Researcher ロール
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
このロールは、Lead Researcher と協働して自身のサイトがプロジェクトに向けて適切に準備されていることを確認する科学者に対して、別のレベルの権限を与えるように設定できます。

スタディごとのロールオーバーライド
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
マルチスタディが設定されている場合(:ref:`multi_study_guide` を参照)、``project.yml`` の ``studies:`` セクションを通じて、ユーザーのロールをスタディごとにオーバーライドできます。例えば、``org_admin`` としてプロビジョニングされたユーザーに、あるスタディでは ``lead`` ロールを、別のスタディでは ``member`` ロールを割り当てることができます。ユーザーが名前付きスタディにログインすると、そのセッション中のスタディスコープの認可の決定には、スタディ固有のロールが使用されます。``default`` スタディでは、常にユーザーの証明書に記載されたロールが使用されます。

FLARE Console(旧称 Admin Client)
------------------------------------------------------------------------
ユーザーのマシン上で動作するコンソールアプリケーションで、コマンドラインインターフェースを通じて NVFLARE のシステム運用操作を行うことができます。

Provisioning Tool
--------------------------
Project Admin がプロジェクトのすべての参加サイトとユーザーをプロビジョニングするために使用するツールです。プロビジョニングツールの出力により、すべての参加者(サイトとユーザー)が相互に安全に通信できるようになります。
