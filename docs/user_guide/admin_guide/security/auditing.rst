監査
========
NVFLARE には、システム内で発生したイベントを記録する監査メカニズムがあります。ユーザーのコマンドイベントと、
学習プロセスによって生成される重要なジョブイベントの両方が記録されます。

監査ログ機構は主に :class:`Auditor<nvflare.fuel.sec.audit.Auditor>` に実装されています。

監査ファイルの場所
^^^^^^^^^^^^^^^^^^^^
監査ファイルは、プロセスの種類に応じて異なるディレクトリに配置されます。

1. Server Parent (SP) 監査ログ:
   - サーバーのルートワークスペースディレクトリに配置されます
   - サーバーのシステムレベルのイベントが含まれます

2. Server Job (SJ) 監査ログ:
   - ジョブのワークスペースディレクトリに配置されます
   - サーバーのジョブ固有のイベントが含まれます

3. Client Parent (CP) 監査ログ:
   - クライアントのルートワークスペースディレクトリに配置されます
   - クライアントのシステムレベルのイベントが含まれます

4. Client Job (CJ) 監査ログ:
   - ジョブのワークスペースディレクトリに配置されます
   - クライアントのジョブ固有のイベントが含まれます

ジョブの監査ファイルにアクセスするには、 `download_job <job_id>` を実行し、ダウンロードされたジョブのワークスペースフォルダー内で
SJ および CJ のログ (デフォルトでは audit.log という名前) を確認してください。

監査ファイルの形式
^^^^^^^^^^^^^^^^^^
監査ファイルはテキストファイルです。ファイル内の各行が 1 つのイベントを表します。各イベントは、ヘッダーと省略可能なメッセージから
構成されます。イベントヘッダーは角括弧で囲まれます。以下はイベントの例です。

.. code-block::

    [E:b6ac4a2a-eb01-4123-b898-758f20dc028d][T:2022-09-13 13:56:01.280558][U:?][A:_cert_login admin@b.org]
    [E:16392ed4-d6c7-490a-a84b-12685297e912][T:2022-09-14 12:59:47.691957][U:trainer@b.org][A:train.deploy]
    [E:636ee230-3534-45a2-9689-d0ec6c90ed45][R:9dbf4179-991b-4d67-be2f-8e4bac1b8eb2][T:2022-09-14 15:08:33.181712][J:c4886aa3-9547-4ba7-902e-eb5e52085bc2][A:train#39027d22-3c70-4438-9c6b-637c380b8669]received task from server

イベントヘッダー
^^^^^^^^^^^^^^^^^^
イベントヘッダーは、イベントに関するメタ情報を指定します。各ヘッダーは、ヘッダータイプ (1 文字) の後にコロン (:) を続け、
さらにヘッダーの値を記述する形式で表現されます。以下は定義されているヘッダータイプとその値です。

.. csv-table::
    :header: ヘッダータイプ,意味,値
    :widths: 5, 10, 20

    E,イベント ID,イベントの ID を表す UUID
    T,タイムスタンプ,イベントの発生時刻
    U,ユーザー,ユーザーの名前
    A,アクション,ユーザーが発行したコマンド、またはジョブのタスク名と ID
    J,ジョブ,ジョブの ID
    S,スコープ,ジョブスコープの名前
    R,リファレンス,ピア側のイベント ID への参照
    M,メッセージ,イベントを説明する省略可能なメッセージ

ほとんどのヘッダーは説明不要ですが、R ヘッダーは例外です。イベントは相互に関連することがあります。たとえば、1 つのユーザーコマンドが
サーバーとクライアントの両方でイベントを記録させることがあります。同様に、クライアントのアクションがサーバーにその処理を行わせること
(クライアントによるタスク結果の送信など) もあります。R ヘッダーはピア側の関連イベント ID を記録します。リファレンスイベント ID は、
システム全体にわたるイベントの相関付けに役立ちます。
